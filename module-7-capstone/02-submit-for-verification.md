## Package your submission

Prepare these five items before you submit. A complete package gets a much more useful review than a screenshot.

### 1. Exported application

- In Studio, open `Course Lab` → **File → Export Application**, or publish to an update set and export the XML.
- Name the file `facilities-request-<yourname>.xml`.

### 2. Self-scored rubric

- Fill in the [self-assessment sheet](01-scoring-rubric.md) with your scores and a one-line evidence note per criterion.
- Be honest. A reviewer's first job is comparing your score to theirs, and the gap is where the learning is.

### 3. Architecture write-up (half a page)

Answer these four questions in plain language:

1. What are your layers, and what is each one responsible for?
2. Where do your priority rules live, and why there?
3. What happens when the weather API is down?
4. What trade-off did you make, and what would you do differently with more time?

### 4. Demo recording (2–4 minutes)

Show, in this order: submitting the catalog item → the created record with temperature and priority → one deliberate failure (break the API URL) and the resulting log entry.

### 5. Code links

Push the exported app and your write-up to a public GitHub repository — `servicenow-portfolio` is a good name. Include a README explaining the architecture. This doubles as your portfolio piece.
